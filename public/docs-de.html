Was ist der Agenten-Konstruktor

Kein Chatbot in der Tasche, sondern ein KI-Mitarbeiter in Ihrem Team.

Was ist der Agent

Das Wesentliche

Der Agent ist Ihr persönlicher KI-Mitarbeiter. Er hat Gedächtnis, Charakter, ein Spezialistenteam und Ihren eigenen Server. Er wird jeden Tag klüger und passt sich an Sie an.

Was der Begriff bedeutet: «Agent» ist Ihr persönlicher Alleskönner mit dem Verstand von Claude Code. Er kann lesen, schreiben, rechnen, planen, Aufgaben erledigen und vieles mehr. Er kennt jeden Ihrer Tage.

Er kommuniziert über einen Telegram-Bot und kann Aktionen auf dem Server ausführen: Dateien lesen und schreiben, Daten analysieren, mit Code arbeiten, Websites und Inhalte erstellen, planen, Kunden antworten usw. Das ist kein Chatbot — nennen Sie ihn nie so, denn Chatbots können das alles nicht.

Aus was er besteht

Der Agent hat drei Bereiche auf dem Server — alle gehören Ihnen:

🤖 Agent
├── Persönlichkeit → ~/workspace/
│     SOUL · MEMORY · USER · CLAUDE
│
├── Spezialisten → ~/workspace/.claude/skills/
│     14 Spezialisten im Team
│
└── Projekte → ~/projects/
      (Ordner mit Ihren Inhalten)

Persönlichkeit — das Herz des Agenten. Hier befinden sich die Dateien SOUL.md (Charakter), MEMORY.md (Gedächtnis über Sie), GOALS.md (Ihre Ziele). Beim ersten Mal vor dem Bot — kann über VS Code gestartet werden.

Spezialisten — 14 Fachleute im Team: Designer, Entwickler, Marketingspezialist, Planer und andere. All das können Sie dem Agenten mit einem einzigen Befehl übertragen.

Projekte — alle Aufgaben: Instagram-Posts, Notizen, Berichte, Content-Pläne usw. Jedes Projekt ist ein eigener Ordner. Jeder Ordner hat sein eigenes memory/ (Aufgabennotizen) und sein eigenes knowledge/ (Arbeitslinks).

Wie er sich von ChatGPT unterscheidet

Ein Chatbot vergisst das Gespräch, sobald Sie das Fenster schließen. Der Agent nicht:

  • Startet sofort mit Kontext — weiß selbst, was offen ist, was erwartet wird, und entwickelt einen Plan
  • Merkt sich unbegrenzt viele Fakten — der Agent schreibt selbst ins Gedächtnis
  • Kennt Ihre Ziele und passt Ratschläge an Sie an
  • Wächst mit dem Agenten-Konstruktor — neue Fähigkeiten und Updates kommen, wenn sie erscheinen
Mein Rat an Sie

Wenn Sie etwas erledigen möchten — geben Sie dem Agenten einfach jede Aufgabe: einen Verkaufsbericht vorbereiten, schnell eine Landing Page erstellen, beim Instagram-Bild helfen. Kannst du das tun, was sollen wir machen? Lassen Sie den Agenten selbst erklären, was er kann und wo er Ihre Hilfe braucht.

So bei jeder Aufgabe. Einfach. Er lernt dabei. Je mehr Aufgaben er löst, desto schneller steigt Ihre Produktivität. Früher haben Sie alles selbst gemacht — jetzt übernimmt der Agent.

Agent-Evolution — wie Ihr Agent immer klüger wird

Der Agenten-Konstruktor wächst jede Woche — Ihr Agent wächst mit ihm.

Der Agenten-Konstruktor entwickelt sich weiter. Neue Skills erscheinen, die Bot-Engine verbessert sich, neue Integrationen kommen heraus. Und all das können Sie buchstäblich mit einem einzigen Befehl zu Ihrem Agenten hinzufügen.

Das Wesentliche

Ich aktualisiere den Agenten-Konstruktor — Sie installieren das Update mit einem einzigen Befehl /new. Ihr Agent wird klüger, ohne Neuinstallation und ohne Datenverlust.

Wie funktioniert das Update

Wenn eine neue Version erscheint:

  1. @jarchitect_bot schreibt Ihnen: «Update verfügbar»
  2. Sie senden den Befehl /new an @jarchitect_bot
  3. Der Bot sendet einen Installationsbefehl (curl | bash)
  4. Sie öffnen das Terminal auf dem Server (über VS Code Tunnel)
  5. Sie fügen den Befehl ein und starten ihn — 1-2 Minuten
  6. Der Agent startet mit neuen Möglichkeiten neu

Was wird aktualisiert

      │
      ↓ Befehl curl | bash
      │
  ┌───┴───┬─────────────────┬──────────────────┐
  │       │                 │                  │
✖ Skills 📄 Vorlagen    🤖 Bot-Engine    ⭐ Neue Features

Skills. Das sind die Spezialisten im Team Ihres Agenten. Es erschien youtube-scenario — der Agent kann Skripte schreiben. Neuer report-builder — erstellt Berichte nach Vorlage. Nach /new funktionieren alle neuen Skills sofort.

Vorlagen (CLAUDE.md, SERVICES.md und andere technische Dateien). Sie verbessern sich, damit der Agent schneller und intelligenter arbeitet. Wie ein Firmware-Update für Ihr Telefon — das Telefon wird besser, Ihre Daten bleiben.

Bot-Engine (~/.agent/bot/index.js). Neue Befehle, Beschleunigungen, Verbesserungen. Vor jedem Update wird ein Backup erstellt — Sie können zurückrollen.

Was sich niemals ändert

Kein Update berührt Ihre Persönlichkeit, Ihr Gedächtnis und Ihre Projekte. Die SOUL.md, die Sie für sich angepasst haben, die MEMORY.md, die der Agent monatelang aufgebaut hat, die Projekte in ~/projects/ — das gehört für immer Ihnen.

Die Engine wird leistungsfähiger — die Seele des Agenten bleibt Ihre.

Mein Rat an Sie

Wenn Sie eine Update-Benachrichtigung sehen — starten Sie es. Das Gedächtnis geht nicht verloren, die Persönlichkeit wird nicht zurückgesetzt, die Projekte verschwinden nicht. Ein Backup wird automatisch vor jeder Installation erstellt.

Agent installieren — vier Schritte bis zum fertigen Bot

Wie ein Umzug in eine neue Wohnung — das Haus steht, die Möbel sind da, es fehlen nur noch die Schlüssel und der Einzug.

Das ist die Hauptanleitung. Der vollständige Weg von null bis zu dem Moment, in dem Ihr Agent Sie persönlich begrüßt und sagt: «Guten Tag, bereit zur Arbeit». Vier Schritte, dreißig bis vierzig Minuten bei einer Tasse Tee. Kein schwarzes Terminal-Fenster wird benötigt.

Hier ist das Gesamtbild: Sie mieten einen kleinen Server im Internet, erstellen einen Telegram-Bot über @BotFather, prüfen Ihr Claude-Abo — und dann geht Claude Code auf Ihrem Laptop selbst auf den Server und richtet dort alles ein. Am Ende öffnen Sie den Server über VS Code und installieren den Agenten-Konstruktor mit einem Befehl.

Das Wichtigste: Die gesamte technische Arbeit erledigt Claude Code. Von Ihnen werden drei «Tickets» benötigt (Server-IP + Passwort, Bot-Token, Claude-Abo) und Enter-Tastendrücke an den richtigen Stellen.

Auf dieser Seite gibt es keine einzige Befehlszeile für das schwarze Terminal-Fenster.

Alles, was wie ein Befehl aussieht, ist entweder Text für den Chat mit Claude Code (er weiß selbst, was damit zu tun ist) oder ein Befehl, den Claude Code dem Server für Sie diktiert. Wenn die Anleitung irgendwann sagt «Terminal öffnen» — dann schauen Sie auf die falsche Seite.

Was VOR dem Start vorbereitet werden muss

  • VS Code und Claude Code auf dem Laptop. Wenn Sie Kursteilnehmer sind — haben Sie das bereits. Wenn Sie von einem Webinar kommen — installieren Sie zuerst VS Code (kostenlos, code.visualstudio.com), dann die Claude Code-Erweiterung (über den VS Code Marketplace, suchen Sie «Claude Code» von Anthropic). Einmal installiert — fertig. Das ist Ihr einziges «Werkzeug» bei dieser Installation.
  • Claude-Abo — Pro oder Max. Pro reicht aus, Max ist komfortabler bei den Limits, aber nicht zwingend. Hauptsache, das Abo ist vorhanden und funktioniert auf Ihrem Laptop im normalen Claude-Chat.
  • Telegram griffbereit. Darüber erstellen wir den Bot und holen am Ende den Prompt bei @jarchitect_bot ab.
  • VPS — gemieteter Server. Für deutschsprachige Nutzer empfehlen sich Hetzner (DE, sehr günstig und zuverlässig) oder DigitalOcean.

VS Code ist ein kostenloser Editor von Microsoft, in den Claude Code als Erweiterung eingebettet wird. Stellen Sie sich ihn als das Fenster vor, in dem Claude lebt. VS Code selbst tut nichts — er gibt Claude einfach ein Zuhause auf Ihrem Laptop.

Claude Code ist Ihr intelligenter Assistent innerhalb von VS Code. Der, dem Sie Aufgaben in menschlicher Sprache geben: «Geh auf den Server, installiere das, verschiebe diese Dateien». Er erledigt alles selbst. Er muss nicht wissen, was SSH ist oder welcher Befehl was bedeutet — er weiß alles.

🎉 Fertig — schreiben Sie Ihrem Agenten in Telegram!

Schritt 1. Server mieten (~5 Minuten)

Gehen Sie zu einem beliebigen Hoster und richten Sie einen VPS ein. Für deutschsprachige Nutzer empfehle ich Hetzner — günstigste Preise in Deutschland, zuverlässig, einfaches Interface. Wenn Ihnen DigitalOcean lieber ist — nehmen Sie das, die Schritte sind ähnlich.

Gehen Sie zum Bereich «Cloud Server» und klicken Sie auf «Server erstellen».

Wählen Sie als Parameter: 2 CPU-Kerne, 4 GB RAM, 40 GB Festplatte, OS Ubuntu 24.04. Diese Parameter reichen für den Agenten aus und bieten Reserven für Speicher- und Projektwachstum auf Jahre hinaus.

VPS ist ein gemieteter kleiner Computer im Internet, der rund um die Uhr läuft. Er steht im Rechenzentrum des Hosters, schaltet sich nicht aus und hat eine eigene Adresse. Sie mieten ihn wie eine Wohnung — bezahlt, Schlüssel erhalten, eingezogen. Nötig, damit Ihr Agent rund um die Uhr arbeitet, auch wenn Ihr Laptop zugeklappt ist.

Etwa 30 Sekunden nach der Bezahlung erhalten Sie eine E-Mail vom Hoster mit drei Zeilen: IP-Adresse des Servers (z.B. 123.45.67.89), Login (root) und Passwort. Speichern Sie das an einem sicheren Ort — das sind die Schlüssel zur neuen Wohnung des Agenten.

Wählen Sie einen Tarif mit ausreichend Speicher — der Agent sammelt mit der Zeit Gedächtnis, Tagesjournale und eine Knowledge-Base an, und der Platz geht schneller zur Neige als man denkt. 40 GB reichen für mehrere Jahre ruhigen Betriebs.

Ein Agent — ein Server

Für einen Agenten ist es besser, einen eigenen VPS zu mieten. Wenn Sie später einen weiteren anlegen möchten (z.B. einen beruflichen und einen privaten) — siedeln Sie ihn auf einem anderen Server an. So arbeitet jeder Agent stabiler und die Erinnerungen werden nicht durcheinander gebracht.

Schritt 2. Bot bei @BotFather erstellen (~3 Minuten)

Öffnen Sie @BotFather in Telegram, drücken Sie Start und schreiben Sie den Befehl /newbot. Er stellt zwei Fragen nacheinander:

  1. Name des Bots — was die Nutzer sehen. Zum Beispiel: «Agent von Anna» oder ein beliebiger schöner Name.
  2. Username — technischer Name. Muss auf bot oder _bot enden und eindeutig sein. Zum Beispiel: anna_agent_bot.

Danach sendet @BotFather einen Token — einen langen String wie 1234567890:AAEh-xxxx.... Kopieren Sie ihn und speichern Sie ihn neben der IP-Adresse des Servers.

BotFather ist der offizielle Telegram-Bot, über den alle anderen erstellt werden. Er gibt jedem neuen Bot einen Token — einen langen String wie einen elektronischen Schlüssel. Mit diesem Token kann der Server dann im Namen Ihres Bots in Telegram schreiben.

Der Bot-Token ist das Passwort Ihres Bots. Zeigen Sie ihn nicht in Chats, veröffentlichen Sie ihn nicht. Falls er versehentlich bekannt wurde — bitten Sie @BotFather um den Befehl /revoke, wählen Sie den Bot aus, erhalten Sie einen neuen Token.

Der Bot antwortet noch nicht auf Nachrichten — das ist normal. Er erwacht nach Schritt 4, wenn der Server mit ihm Bekanntschaft macht.

Schritt 3. Claude-Abo prüfen (~1 Minute)

Öffnen Sie claude.ai im Browser und melden Sie sich an. Wenn Sie im oberen Menü den Status Pro oder Max sehen — alles gut, weiter geht's. Wenn der Status Free ist — schließen Sie Pro in den Profileinstellungen ab.

Das Claude-Abo ist Ihr Konto auf claude.ai, über das Sie den normalen Chat nutzen. Der Agent arbeitet über dasselbe Abo — Limits kommen von dort, für seinen Betrieb fallen keine zusätzlichen Kosten an.

Stellen Sie sicher, dass Sie Login/Passwort des Claude-Kontos kennen — sie werden beim Autorisierungsschritt auf dem Server in Schritt 4 benötigt.

Schritt 4. Installation über Claude Code starten (~30 Minuten)

Der größte, aber interessanteste Schritt. Hier geht Claude Code auf dem Laptop selbst auf Ihren Server und installiert alles.

Es gibt zwei Teile: zuerst den Server einrichten (Teil A, ~20 Minuten), dann den Agenten-Konstruktor über den persönlichen Prompt installieren (Teil B, ~2 Minuten).

Teil A. Server-Installation mit lokalem Claude Code

Öffnen Sie VS Code auf dem Laptop. Erstellen Sie einen beliebigen Ordner auf dem Desktop — z.B. agent-setup — und öffnen Sie ihn in VS Code (File → Open Folder). Starten Sie Claude Code.

Kopieren Sie diesen Installations-Prompt in Claude Code, ersetzen Sie die drei Werte durch Ihre eigenen und drücken Sie Enter:

Lade die Anleitung herunter von
https://raw.githubusercontent.com/Ntmib/jarvisarchitect/main/server/INSTALL-SERVER.md
und führe alles aus, was darin steht.

IP: 123.45.67.89
Passwort: ihr-server-passwort
Telegram-Bot: 1234567890:AAEh-xxxxxxxxxxxxxxxxxxxxxxxx

Ersetzen Sie:

  • 123.45.67.89 → Ihre echte IP aus der Hoster-E-Mail
  • ihr-server-passwort → Ihr Root-Passwort
  • 1234567890:AAEh-xxxx... → Ihr Token von @BotFather

Passwort und Token schreiben Sie direkt in den Claude Code-Chat auf dem Laptop. Sie gehen nirgendwo weiter — Claude Code speichert sie nur in dieser Unterhaltung. Nach der Installation können Sie das Passwort über die Hoster-Oberfläche ändern und den Token über /revoke bei @BotFather. Beide haben ihre Aufgabe dann bereits erfüllt.

Danach führt Sie Claude Code an der Hand. Er verbindet sich selbst mit dem Server, entfaltet die Programme, startet den Telegram-Bot als Dienst. Vor jedem Schritt erklärt er in einem Satz, was er tun wird, danach — was erreicht wurde.

Was Claude Code Schritt für Schritt tun wird:

  1. Verbindung mit Ihrem Server per SSH herstellen
  2. Grundprogramme installieren — Node.js, Claude Code CLI
  3. Einen eigenen Benutzer agent auf dem Server anlegen
  4. Grundlegende Skills installieren (fertige Rollen: Autor, Scout, Entwickler, Designer)
  5. Den Telegram-Bot als 24/7-Dienst starten
  6. Sie einmalig um die Claude-Autorisierung auf dem Server bitten (über einen Link)
  7. VS Code Tunnel einrichten, damit Sie den Server aus dem normalen VS Code öffnen können

Claude-Autorisierung auf dem Server

Irgendwann wird Claude Code schreiben: «Öffnen Sie diesen Link, melden Sie sich mit Ihrem Claude-Konto an und klicken Sie auf Authorize». Das ist einmalig nötig — damit der Agent auf dem Server über Ihr Abo arbeiten kann. Öffnen Sie den Link im Browser, melden Sie sich wie gewohnt an, klicken Sie auf die große Schaltfläche Authorize.

Wenn der Browser einen Fehler anzeigt — kein Grund zur Panik

Das ist eine bekannte Kleinigkeit bei Safari. Öffnen Sie einfach denselben Link in Chrome oder Firefox — es funktioniert auf Anhieb. Nichts ist kaputt.

Nach der Autorisierung kehren Sie zu Claude Code zurück und sagen «fertig» — er macht weiter.

Wenn die Installation abgeschlossen ist, schreibt Claude Code einen kurzen Bericht: was installiert wurde, was als nächstes zu tun ist. Der Telegram-Bot lebt zu diesem Zeitpunkt bereits — schreiben Sie Ihrem Bot in Telegram /start, er sollte antworten.

Teil B. Agenten-Konstruktor installieren

Wenn der Telegram-Bot auf /start geantwortet hat — ist der Server bereit. Jetzt installieren wir den Konstruktor.

Öffnen Sie @jarchitect_bot in Telegram und schreiben Sie /get. Der Bot sendet Ihren persönlichen Prompt und eine Schritt-für-Schritt-Anleitung, was damit zu tun ist.

Der Prompt ist persönlich und funktioniert einmalig — das ist das Sicherheitssystem. Falls etwas schiefgelaufen ist oder der Prompt verbraucht wurde — schreiben Sie dem Bot /new, er stellt einen neuen aus.

Fertig — der Agenten-Konstruktor ist installiert

Wenn der Konstruktor installiert ist, liest Ihr Agent automatisch die Kerndateien (CLAUDE.md, SOUL.md, MEMORY.md, GOALS.md) und begrüßt Sie. Schreiben Sie etwas — das ist bereits das erste Gespräch.

Was Sie jetzt haben:

  • Server in der Cloud, arbeitet 24/7
  • Telegram-Bot antwortet auf Ihre Nachrichten über Ihr Claude-Abo
  • Agenten-Konstruktor ist installiert und wartet auf das erste Gespräch
  • VS Code Tunnel — Sie können den Server von jedem Computer mit VS Code aufrufen

Wenn etwas schiefgelaufen ist

Prompt von @jarchitect_bot bereits verwendet oder abgelaufen → schreiben Sie dem Bot /new, er stellt einen neuen aus. Ein Prompt funktioniert einmalig — das ist Absicht, aus Sicherheitsgründen.

Claude Code sagt «Verbindung fehlgeschlagen» → wahrscheinlich blockiert der Provider den SSH-Port. Das ist selten — schreiben Sie an @aibasis_bot, wir lösen das. Versuchen Sie nicht, es manuell zu reparieren, öffnen Sie nicht die Web-Oberfläche des Hosters (Paste aus der Zwischenablage ist dort oft kaputt und Sie werden sich nur müde machen).

Alle anderen typischen Situationen sind im Abschnitt Troubleshooting beschrieben — schauen Sie rein und suchen Sie Ihren Fall.

Mein Rat an Sie

Hetzen Sie bei der Installation nicht. Das passiert einmalig, und es ruhig zu tun ist wichtiger als schnell. Bevor Sie in Schritt 4 mit Passwort und Token Enter drücken — prüfen Sie, ob Sie alle drei Platzhalter ersetzt haben. Das ist der häufigste kleine Fehler: «IP vergessen» oder «Passwort nicht ersetzt».

Und während das lokale Claude Code den Server einrichtet — sitzen Sie nicht daneben und aktualisieren Sie den Chat nicht alle 10 Sekunden. Das ist ein normaler Prozess, er arbeitet still. Machen Sie sich einen Tee, machen Sie eine Pause. Nach 15–20 Minuten kommen Sie zurück — Server und Bot sind bereit, es bleibt nur Teil B.

Wie geht es weiter

Wenn der Konstruktor Sie begrüßt hat und Sie Dateien in ~/jarvis-bonus/ sehen — direkt weiter zu «Erste Schritte am ersten Tag». Dort erfahren Sie, wie Sie den Konstruktor wirklich kennenlernen, ihm von sich erzählen und die erste echte Aufgabe stellen.

Die Karte des Agenten-Hauses — was wo auf dem Server liegt

Der Agent hat drei Räume — Motor, Seele und Werkstatt. Kennen Sie die Karte, verlieren Sie sich nie.

Wenn Sie über VS Code Tunnel einen Blick zu Ihrem Agenten werfen möchten — hilft diese Karte seines Zuhauses. Damit Sie wissen, was in welchem Raum liegt und wo man besser nicht herumhantiert. Dieser Artikel ist ein kurzer Grundriss.

Hauptbotschaft

Kernaussage

Der Agent hat drei Bereiche auf dem Server: System (Motor), Persönlichkeit (Seele) und Projekte (Werkstatt). Kennen Sie diese Karte — verlieren Sie sich nie, was man anfassen darf und was nicht.

Die vollständige Karte

🏠 /home/agent/
 │
 ├── 🔧 ~/.agent/          ← Motor (NICHT anfassen)
 │    └─ bot · sessions · .env · state.json
 │
 ├── 💜 ~/workspace/       ← Seele (bedenkenlos bearbeiten)
 │    └─ SOUL · MEMORY · GOALS · skills · memory/ · knowledge/
 │
 └── 🔨 ~/projects/        ← Werkstatt (Arbeitsprojekte)
      └─ Landing Pages · Bots · Berichte · Content

Bereich 1 — Motor (~/.agent/)

Das ist der Systemordner. Hier lebt der Bot selbst, API-Schlüssel, Einstellungen, Sitzungshistorie, Backups früherer Versionen. Der Agent darf dort nicht schreiben — read-only, damit nichts versehentlich kaputtgemacht wird.

🔧 ~/.agent/
 ├─ bot/           ← Telegram-Bot-Engine
 │   ├─ index.js
 │   └─ versions/  ← Backups alter Versionen (zum Zurückrollen)
 ├─ sessions/      ← Gesprächshistorie (auto-gelöscht nach 7 Tagen)
 ├─ traces/        ← Logs zur Fehlersuche
 ├─ .env           ← API-Schlüssel (Zugriff nur für Eigentümer)
 └─ state.json     ← Modelleinstellungen, Limits, Zeitplan
Hier besser nicht manuell eingreifen

Diese Dateien werden nur vom Bot «Agenten-Konstruktor» bei Installation und Updates angefasst. Wenn hier etwas kaputt gemacht wird — hört der Agent auf zu funktionieren. Wollen Sie Einstellungen ändern (Modell, Limit, Zeitplan)? Nutzen Sie /settings im Chat mit dem Agenten — das ist sicher und komfortabel.

Bereich 2 — Seele (~/workspace/)

Das ist das Herz des Agenten. Hier lebt alles, was Ihren Agenten zu Ihrem macht: Charakter, Gedächtnis über Sie, Ihre Ziele, Ihre Vorlieben, Ihr Spezialistenteam. Hier können Sie bedenkenlos alles bearbeiten — nichts geht kaputt.

💜 ~/workspace/
 │
 ├─ Persönlichkeitsdateien (8 Hauptdateien des Agenten)
 │   ├─ SOUL.md         ← Charakter, Ton, Stil
 │   ├─ MEMORY.md       ← Langzeitgedächtnis über Sie
 │   ├─ GOALS.md        ← Ihre aktuellen Ziele
 │   ├─ USER.md         ← Ihr Profil (Rolle, Erfahrung, Kontext)
 │   ├─ MISSION.md      ← Mission des Agenten
 │   ├─ PROJECTS.md     ← Liste aktiver Projekte
 │   ├─ PREFERENCES.md  ← Ihre Arbeitsvorlieben
 │   └─ LEARNED.md      ← Erkenntnisse des Agenten aus der Arbeit mit Ihnen
 │
 ├─ Konfiguration
 │   ├─ CLAUDE.md       ← Verhaltensregeln (was immer zu tun ist)
 │   ├─ SERVICES.md     ← Katalog Ihrer Dienste und APIs
 │   └─ DATA-POLICY.md  ← Richtlinien zur Datenverarbeitung
 │
 ├─ .claude/skills/     ← 14 Spezialisten (writer · designer · researcher...)
 │
 ├─ memory/             ← Tagebuch: JJJJ-MM-TT.md für jeden Tag
 ├─ knowledge/          ← Wissensbasis (Artikel, Lösungen, Configs)
 ├─ content/            ← Content-Materialien

«Ampel»: was der Agent selbst tut, was er zeigt, was er fragt

Ampeln gibt es nicht nur auf Straßen. Jede Aktion des Agenten durchläuft drei Farben — und das ist kein Zufall.

Der Agent hat keine Initiative, alles Beliebige zu tun. Jede Aktion fällt in eine von drei Stufen — grün, gelb, rot. Das sind Regeln aus CLAUDE.md, die bestimmen, wie selbstständig der Agent handelt. Das System heißt «Ampel» und ist wörtlich festgelegt.

Hauptbotschaft

Umkehrbarkeit — das Hauptkriterium

Grün — was leicht rückgängig zu machen ist oder den Zustand gar nicht ändert. Rot — was nicht widerrufbar ist oder externe Dienste mit Kosten betrifft. Gelb — dazwischen: tut es, zeigt es aber. Drei Fragen: «Ändert das etwas?» → «Kann man es rückgängig machen?» → «Kostet das Geld?»

Grün — macht es selbst

Der Agent führt ohne Warnung aus:

  • Lesen und Suchen in Dateien im workspace-Ordner
  • Internetsuche, Lesen öffentlicher Seiten
  • Notizen erstellen in memory/ und knowledge/

Das ändert Ihre Dateien nicht und betrifft keine externen Dienste. Der Agent kann lesen, suchen und Notizen schreiben — und wird jedes Mal keine Erlaubnis fragen.

Gelb — macht es und zeigt es

Der Agent führt aus, meldet aber die Aktion:

  • Erstellen und Bearbeiten von Dateien im Projekt
  • git status, git diff, git add, git commit
  • Sichere Installationsbefehle: npm, pip, brew

Datei erstellt oder geändert — der Agent zeigt, was genau er getan hat. Commit hinzugefügt — schreibt darüber. Das sind Aktionen, die Spuren hinterlassen und überprüft werden können.

Rot — Stopp, fragt und wartet

Vor roten Operationen zeigt der Agent den Plan und wartet auf oder :

  • Löschen: rm, rm -rf, Ordner löschen
  • Destruktives Git: push --force, reset --hard, branch -D
  • Kostenpflichtige APIs und Bezahlung: alle Aktionen, die Geld kosten
  • Alles Unwiderrufliche: was nicht rückgängig gemacht werden kann

Wenn der Agent etwas nicht getan hat und einen Plan geschrieben hat — das war eine rote Operation. So soll es sein.

Gesperrte Zonen

Drei Pfade auf dem Server, die der Agent unter keinen Umständen liest oder ändert:

~/.agent/.env        — Geheimnisse (Token, Schlüssel)
~/.agent/bot/        — Code des Bots selbst (read-only)
~/.agent/state.json  — Bot-Konfiguration

Das ist weder «gelb» noch «rot» — das ist ein Verbot. Auch wenn Sie darum bitten — der Agent lehnt ab und erklärt warum.

Mein Rat an Sie

Wenn Sie sehen, dass der Agent ständig um Erlaubnis für etwas bittet, das Ihnen einfach erscheint — prüfen Sie, ob diese Aktion in die rote Liste fällt. Höchstwahrscheinlich sieht der Agent ein Risiko, das auf den ersten Blick nicht offensichtlich ist.

Und umgekehrt: wenn der Agent etwas getan hat, ohne zu fragen — das ist grüne oder gelbe Stufe. Das bedeutet nicht, dass er «eigenmächtig» handelt — es bedeutet, dass die Regeln dies erlauben.

    Der Agent liest, wer er ist, wie er anspricht, was er tut und was er nicht tut. Das ist das Erste, was er liest — weil der Arbeitsstil vom allerersten Wort an benötigt wird.

  2. MEMORY.md — Langzeitgedächtnis.

    Wer Sie sind, Ihre Projekte, wichtige Entscheidungen, die der Agent sich merken soll. Hier stehen dauerhafte Fakten — sie ändern sich nicht von Sitzung zu Sitzung.

  3. GOALS.md — was jetzt wichtig ist.

    Aktuelle Ziele und Prioritäten. Der Agent versteht, worauf er in der Arbeit den Schwerpunkt legen soll.

  4. Dateien aus memory/ der letzten 3 Tage — letzte Entscheidungen und Kontext.

    Sitzungstagebücher mit Details — was vorgestern, gestern, heute gemacht wurde. Hier ist der operative Kontext: unfertige Aufgaben, Vereinbarungen, Arbeitsstand.

  5. _progress.md — falls im Projekt vorhanden.

    Wenn der Agent in der letzten Sitzung an einer Aufgabe gearbeitet und eine Fortschrittsdatei hinterlassen hat — liest er sie und macht dort weiter.

Warum genau diese Reihenfolge

Zuerst — Persönlichkeit (SOUL.md), dann — Langzeitgedächtnis (MEMORY.md), dann — aktuelle Ziele (GOALS.md), dann — operativer Kontext (Tagebücher). Das ist eine logische Reihenfolge: zuerst «erinnert sich» der Agent an sich selbst, dann «erinnert er sich» an Sie, dann versteht er, was gerade wichtig ist.

Wäre die Reihenfolge umgekehrt — würde der Agent die letzten Ereignisse kennen, aber nicht wissen, in welchem Stil er sie besprechen soll.

Was «normaler Chat» bedeutet

Wenn Sie all diese Dateien löschen oder Claude Code in einem leeren Ordner starten — erhalten Sie einen Standard-Claude ohne Gedächtnis und ohne Personalisierung. Er kennt Ihren Namen nicht, Ihre Projekte nicht, Ihre Präferenzen nicht. Genau das Vorhandensein und die Qualität dieser Dateien bestimmt, wie sehr der Agent Sie «spürt».

Mein Rat an Sie

Wenn der Agent sich plötzlich «anders» verhält — prüfen Sie zuerst SOUL.md und MEMORY.md. Höchstwahrscheinlich hat sich etwas darin verändert oder wurde nicht notiert. Die Dateien sind das einzige «Gedächtnis» zwischen den Sitzungen. Keine Aufzeichnung — kein Gedächtnis.

Bot-Befehle — kurze Referenz

Fünf Buttons für jeden Tag und fünf für besondere Fälle. Kennen Sie alle zehn — und der Agent liegt in Ihren Händen.

Im Chat mit Ihrem Agenten stehen zehn Befehle zur Verfügung. Die meisten nutzen Sie täglich, einige halbjährlich, und ein paar vielleicht nie. Dieser Artikel ist eine kurze Referenz: was jeder Befehl tut, wann Sie ihn verwenden, und welche Gewohnheiten Ihnen helfen, Limit und Zeit zu sparen.

Das Wichtigste

Fünf Befehle für die tägliche Arbeit — sichtbar im Telegram-Menü beim Tippen von /.
Fünf für besondere Fälle — diese geben Sie manuell ein, wenn nötig.
Kennen Sie alle zehn — und der Agent ist vollständig in Ihrer Hand.

Die fünf aus dem Telegram-Menü

Diese Befehle erscheinen direkt im Vorschlag, wenn Sie im Chat mit dem Agenten «/» tippen.

/start — Hauptmenü

Wenn der Agent bereits eingerichtet ist — kurze Begrüßung mit Befehlsliste. Wenn der Agent gerade installiert wurde — startet die Einrichtung (Bootstrap): fragt Ihren Namen, Tätigkeit, Ziele. Die Antworten werden zu Persönlichkeitsdateien (USER.md, GOALS.md, MEMORY.md).

Wann verwenden:

  • Beim allerersten Mal nach der Installation — zwingend erforderlich, sonst wird der Agent nicht Ihr persönlicher.
  • Im Alltag — kaum, außer Sie haben die Befehle vergessen.

/stop — Aufgabe anhalten

Unterbricht, was der Agent gerade macht. Der Prozess wird sanft beendet (SIGTERM), nach 3 Sekunden hart (SIGKILL). «⏳ Denke nach...» wechselt zu «⏹ Aufgabe gestoppt».

Wann verwenden:

  • Der Agent schreibt länger als 5 Minuten und es scheint, als wäre er hängengeblieben. Manchmal ist das nur ein Eindruck — bei großen Aufgaben kann der Agent 10–20 Minuten denken.
  • Der Agent sendet plötzlich viele Nachrichten, ohne dass Sie es verlangt haben.
  • Sie haben es sich anders überlegt — langen Bericht angefordert, jetzt möchten Sie eine kurze Zusammenfassung.

Wichtig: /stop bricht nur die aktuelle Aufgabe ab. Der Gesprächskontext bleibt erhalten — Sie können sofort weitermachen.

/reset — neue Sitzung (wichtigster Befehl zum Limit sparen)

Löscht den Kontext der aktuellen Unterhaltung: Der Agent vergisst alles, was in dieser Sitzung besprochen wurde. Das Langzeitgedächtnis (MEMORY.md, USER.md, GOALS.md) bleibt unberührt — diese Dateien werden bei jedem Start neu gelesen.

Warum /reset Geld spart

Das ist die wichtigste Gewohnheit im Umgang mit dem Agenten. Jede Nachricht in einer aktiven Sitzung überträgt den gesamten bisherigen Gesprächsverlauf — und Sie bezahlen dafür mit Tokens. Mit /reset beginnt die nächste Aufgabe mit leerem Kontext.

Öffnet ein Inline-Menü mit sechs Registerkarten: Modell, Modus, Umgebungsvariablen (API-Schlüssel), Zeitzone, Tageslimit, Neustart.

Kurze Übersicht mit Ampel für Tagesverbrauch:

  • grün — alles in Ordnung
  • gelb — nahe am Limit
  • rot — Limit erreicht, neue Anfragen bis morgen gesperrt

Sprache — Deepgram, Whisper und Tricks

Einmal einrichten — und jahrelang mit dem Agenten sprechen wie mit einem echten Assistenten.

Sprache ist das praktischste Feature des Agenten. Sie gehen die Straße entlang, sprechen eine Aufgabe ein — der Agent transkribiert und legt los. In diesem Artikel: wie Sprache intern funktioniert, welche Verbindungsoptionen es gibt, und ein paar Lifehacks für maximalen Nutzen.

Das Wichtigste

  • Deepgram (Cloud, hohe Genauigkeit) — $200 Gratisguthaben bei Registrierung reicht für Jahre.
  • Whisper (lokal, dauerhaft kostenlos) — läuft auf Ihrem Server. Etwas schlechtere Qualität, 8 Min. Installation.

In 99% der Fälle wird Deepgram gewählt — schnell, genau, und dank Bonus de facto kostenlos.

Wie der Agent wählt

  1. Deepgram-Schlüssel vorhanden → immer Deepgram.
  2. Kein Schlüssel, Whisper installiert → Whisper.
  3. Nichts → Menü beim ersten Sprach-Input.

Deepgram verbinden

  1. console.deepgram.com → Registrierung → $200 Guthaben.
  2. API Keys → Create a New API Key → Name (z.B. agent-factory).
  3. Schlüssel kopieren (wird einmal angezeigt).
  4. /settings → 🔑 Umgebungsvariablen → Deepgram → Schlüssel senden.
  5. Bot löscht Nachricht, speichert sicher. Sprache funktioniert sofort.

Technisch: Modell nova-2 mit smart_format — Zahlen, Daten und Satzzeichen automatisch formatiert. Transkription in 1–3 Sekunden.

Whisper — kostenlose Alternative

Lokal auf Ihrem Server, kein Internet, keine Rechnung.

Wann Whisper: keine Daten nach außen geben möchten, oder grundsätzlich nie bezahlen.

Nachteile: schlechtere Qualität, 8 Min. Installation, 5–15 Sek. Transkriptionszeit.

Installation: bei erster Sprachnachricht ohne Deepgram → Button «🔧 Whisper installieren».

Lifehacks

Keine Angst vor langen Sprachnachrichten

Telegram erlaubt unbegrenzt lange Sprachnachrichten. Sprechen Sie 5–10 Minuten — der Agent transkribiert alles. Ideal für: Projekt-Brief, detaillierte Aufgabenbeschreibung, «Gedankentagebuch» laut.

Sprechen Sie natürlich

«Hör mal, ich brauche morgen einen Verkaufsbericht für April. Zahlen in der Google-Tabelle. Was gestiegen ist, was gefallen, drei Hypothesen zur Verbesserung.» Je natürlicher die Sprache, desto besser versteht der Agent.

Zahlen und Daten

«Siebenhundertfünfzig Kunden im Juli» → 750 Kunden im Juli. «Fünfzehnter Mai um neun» → 15. Mai um 9:00. Das macht smart_format.

Wann Text besser ist

  • API-Schlüssel und Passwörter — nie per Sprache.
  • Lange technische Begriffe oder Fremdnamen.
  • Komplexe Zahlentabellen.

Problembehebung

«Transkribiere...» hängt: Deepgram — normal 1–3 Sek., über 30 Sek. = Problem. /status prüfen, neu versuchen. Whisper — normal 5–15 Sek., bei schwachem Server bis 1 Min.

Text mit Fehlern: Korrigieren per Text: «Ich meinte nicht X, sondern Y.»

$200-Guthaben aufgebraucht: $5–10 nachladen (hunderte Stunden Transkription) oder auf Whisper umsteigen.

Mein Rat

Deepgram am ersten Tag einrichten — und dieses Thema für Jahre vergessen. Das Guthaben reicht so lange, dass Sie erst den Agenten kennenlernen, ein paar Projekte aufbauen, und dann erst die erste Rechnung sehen werden.

Sitzungen und /reset — wann Gespräch «vergessen»

Die Sitzung ist das Notizbuch des aktuellen Gesprächs. /reset — schließen und ein neues nehmen. Persönlichkeit und Gedächtnis des Agenten — seine Bücher im Regal, die bleiben.

Jedes Mal wenn Sie dem Agenten schreiben, antwortet er nicht «von Null» — er erinnert sich an das gesamte vorherige Gespräch. Das ist die Sitzung. Zu verstehen wie sie funktioniert — nicht zwingend. Aber zu wissen wann man sie zurücksetzen soll — das ist die wichtigste Gewohnheit für alle, die täglich mit dem Agenten arbeiten.

Das Wichtigste

Sitzung — das ist die Geschichte des aktuellen Gesprächs. Der Agent erinnert sich an alles was darin besprochen wurde.

/reset — schließt die Sitzung. Die nächste Nachricht beginnt auf einem leeren Blatt.

Wichtig: bei /reset geht nur das Gespräch verloren. Persönlichkeit des Agenten, sein Gedächtnis über Sie, Ihre Ziele, Projekte — alles bleibt. Diese Dinge leben in Dateien, nicht in der Sitzung.

Was in der Sitzung gespeichert ist

Die Sitzung ist die vollständige Gesprächsgeschichte für den aktuellen Unterhaltungszeitraum:

  • Alle Ihre Nachrichten,
  • Alle Antworten des Agenten,
  • Alle Aktionen die er ausgeführt hat (Dateien gelesen, Programme installiert, im Internet gesucht),
  • Alle Daten die ihm zugekommen sind (Transkriptionen von Sprachnachrichten, Dokumenteninhalt, Links).

Wenn Sie eine neue Nachricht schreiben — nimmt der Agent die gesamte Geschichte und sendet sie mit der neuen Frage an Claude. Deshalb kann er antworten «erinnerst du dich, du hast mir vor 20 Minuten von X erzählt» — er erinnert sich wirklich.

Technisch ist jede Sitzung eine Datei auf dem Server (~/.claude/projects/.../sessionId.jsonl), in die jede neue Nachricht geschrieben wird.

Was NICHT in der Sitzung ist — und bei /reset nicht verloren geht

Das ist entscheidend zu verstehen. Wenn Sie /reset ausführen, vergisst der Agent nichts Wichtiges. Aus der Sitzung geht nur das Gespräch selbst. Es bleibt alles:

Was bleibtWo gespeichert
Persönlichkeitsdateien — SOUL.md, MEMORY.md, USER.md, GOALS.md ~/workspace/ — bei jeder Anfrage neu gelesen
Alle Ihre Projekte in ~/projects/ Dateien auf dem Server, nicht an Sitzung gebunden
Wissensbasis in ~/workspace/knowledge/ Ihre Entscheidungen, Konfigurationen, wichtige Links
Alle Skills und verbundene Dienste (Deepgram, GitHub, OpenRouter) Konfiguration in /settings
Tagebücher in ~/workspace/memory/YYYY-MM-DD.md Agent schreibt sie täglich selbst

💬 Einfache Analogie: die Sitzung ist Ihr Notizbuch für das aktuelle Gespräch. /reset — Notizbuch geschlossen, neues genommen. Alle Bücher des Agenten im Regal (Persönlichkeit, Gedächtnis, Projekte, Skills) sind unberührt.

Warum /reset Limit spart

Das ist das Wichtigste und am wenigsten Offensichtliche für neue Nutzer. Jede Nachricht in einer aktiven Sitzung verarbeitet Claude mit der gesamten bisherigen Geschichte — je länger das Gespräch, desto mehr Tokens kostet jede neue Antwort.

Einfaches Beispiel:

  1. Morgens 2 Stunden Vertriebsplan besprochen. In der Sitzung ~30.000 Tokens Geschichte angesammelt.
  2. Nach dem Mittagessen schreiben Sie «hilf mir einen Instagram-Post zu schreiben».
  3. Ohne /reset: Agent nimmt 30.000 Tokens Vertriebsgeschichte + neue Post-Anfrage. 99% der Geschichte — überflüssig. Aber Sie bezahlen dafür.
  4. Mit /reset: neue Sitzung, ~0 Tokens Geschichte. Verbrauch zigfach geringer.

Bei aktiver Arbeit: 1 Stunde Gespräch = ~20.000–50.000 Tokens angesammelter Kontext. Ohne /reset-Gewohnheit kann man 5–10× mehr Kontingent verbrauchen als nötig.

Was der Agent automatisch macht

Auto-Komprimierung bei 90%

Claude kann die Geschichte komprimieren, wenn sie fast das Limit erreicht (~200.000 Tokens bei Sonnet, ~1.000.000 bei Opus). Die Komprimierung ist ein automatisches «Zusammenfassen» alter Nachrichten. Sie werden es nicht bemerken, das Gespräch geht weiter. Aber das ist eine Notfallmaßnahme — deshalb bleibt /reset trotzdem die Hauptgewohnheit.

Auto-Rotation bei 2 MB

Wenn die Sitzungsdatei auf der Festplatte über 2 MB wächst — startet der Agent automatisch eine neue Sitzung. Sie erhalten eine Antwort, aber der Gesprächskontext wird zurückgesetzt. Das ist eine Absicherung für eine seltene Situation — tritt meist auf wenn Sie viele Fotos und Dokumente in einer Sitzung senden.

Crash Recovery — Wiederherstellung nach Absturz

Wenn der Agent mitten in einer Aufgabe abstürzt (z.B. Server-Neustart), speichert er die letzte Anfrage und die unfertige Antwort in .crash_context.md. Wenn Sie die nächste Nachricht schreiben — wird diese Information automatisch in die neue Anfrage eingemischt. Der Agent sagt «das war vor dem Absturz, ich mache weiter». Funktioniert einmal, danach wird die Datei gelöscht.

Wann /reset obligatorisch ist

  • Jeden Morgen — Überreste des gestrigen Gesprächs schließen. Gewohnheit Nummer eins.
  • Vor einem neuen Thema, das nichts mit dem vorherigen zu tun hat.
  • Nach einer großen Aufgabe (1–2 Stunden Gespräch) — eine frische Sitzung antwortet oft präziser.
  • Wenn der Agent anfängt sich zu «verwirren» — seltsam antwortet, Themen vermischt, falsche Dinge tut. Oft hilft ein einfaches /reset.
  • Vor einer sensiblen Aufgabe — Sie möchten nicht, dass Details aus früheren Gesprächen in die neue Anfrage einfließen.

Häufige Fragen

«Vergisst der Agent nach /reset wer ich bin?»

Nein. Persönlichkeit (SOUL.md), Gedächtnis (MEMORY.md), Profil (USER.md), Ziele (GOALS.md) — alles Dateien auf dem Server, nicht in der Sitzung. Der Agent liest sie bei der nächsten Anfrage erneut.

«Gehen nach /reset meine Projekte verloren?»

Nein. Alle Projekte in ~/projects/ — Dateien auf dem Server. Nach /reset sind sie vorhanden.

«Was ist besser — /reset oder einfach den Chat schließen?»

/reset — besser. Das Schließen des Chats setzt nichts zurück: die Sitzung lebt auf dem Server, und wenn Sie zurückkehren — macht der Agent weiter wo er aufgehört hat. /reset ist der einzige Weg, mit einem leeren Blatt zu beginnen.

«Kann ich das Gespräch nach /reset wiederherstellen?»

Nein — nach /reset wird die Sitzung aus der aktiven Liste gelöscht. Wenn das Gespräch wichtig war — bitten Sie den Agenten, das Ergebnis in ~/workspace/memory/YYYY-MM-DD.md zu speichern, bevor Sie /reset ausführen.

Mein Rat

Merken Sie sich eine Formel:

Jedes neue Thema = /reset. Jeden Morgen = /reset.

Diese 5 Sekunden sparen hunderte Dollar Kontingent im Monat und machen die Antworten des Agenten präziser. Noch keine Gewohnheit — pinnen Sie eine Erinnerung «/reset nicht vergessen» im Telegram-Chat mit dem Agenten, bis es zum Reflex wird.

Und denken Sie daran: /reset verliert nichts Wichtiges. Alle Ihre Daten, die Persönlichkeit des Agenten, Projekte, Skills — sind vorhanden. Nur das aktuelle Notizbuch des Gesprächs wird zurückgesetzt.

Drei Gedächtnisebenen des Agenten — warum er klüger ist als ChatGPT

Drei Hefte auf dem Schreibtisch eines tüchtigen Assistenten — Notizbuch, Tagebuch, Bibliothek. Jedes kennt seine Aufgabe.

Viele denken: «Der Agent ist einfach ChatGPT mit mehr Gedächtnis». Und verpassen dabei das Wesentliche. Der Agent hat nicht ein Gedächtnis — er hat drei Ebenen. Jede Ebene erfüllt ihre Aufgabe: eine erinnert für immer, eine führt die Tageschronik, eine speichert tiefe Nachschlagewerke zu Themen. Deshalb wird der Agent tatsächlich klüger mit Ihnen — und setzt sich nicht jeden Morgen wie ein Chatbot zurück.

Die wichtigste Botschaft

Das Gedächtnis gehört Ihnen, nicht uns

Alle drei Gedächtnisebenen liegen im Ordner ~/workspace/ auf Ihrem Server. Das sind gewöhnliche Textdateien. Wenn Sie möchten, kopieren Sie den Ordner — und die gesamte «Seele» des Agenten liegt in Ihrer Tasche. Wir aktualisieren nur die Engine. Alles, was der Agent über Sie und Ihre Projekte weiß — gehört Ihnen.

Warum drei und nicht eins

Wenn beim Agenten alles in einem Haufen liegt, ertrinkt er entweder in Details («was haben wir im Februar gemacht?») oder vergisst Wichtiges («was ist Ihr Geschäft?»). Drei Ebenen — das sind drei Hefte auf dem Schreibtisch eines tüchtigen Assistenten:

  • Notizbuch — Schlüsselfakten über Sie. Wird jeden Tag neu gelesen.
  • Tagebuch — was heute war. Ein Blatt pro Tag.
  • Bibliothek — tiefe Nachschlagewerke zu Themen, die aufgetaucht sind.

Jedes löst seine Aufgabe. Und zusammen erhalten Sie einen Agenten, der sich an das gestrige Gespräch erinnert, Ihren Stil kennt und dabei nicht in Details verloren geht.

Gedächtniskarte

~/workspace/
├── MEMORY.md          ← Ebene 1: Langzeitgedächtnis (≤200 Zeilen)
├── memory/
│   ├── 2026-05-10.md  ← Ebene 2: Tagesjournal
│   ├── 2026-05-09.md
│   └── ...
└── knowledge/         ← Ebene 3: thematische Nachschlagewerke
    ├── billing-flow.md
    ├── server-setup.md
    └── ...

Alle drei sind gewöhnliche .md-Dateien. Sie öffnen sich in jedem Editor. Sie können hineinschauen, bearbeiten, ergänzen — der Agent liest beim nächsten Start alles neu.

Ebene 1 — MEMORY.md (Notizbuch)

Das sind die wichtigsten Fakten, die der Agent immer wissen muss. Wer Sie sind, womit Sie sich beschäftigen, welche Projekte Sie leiten, welche Vorlieben Sie haben. Wird jedes Mal neu gelesen, wenn Sie den Chat öffnen.

Eine Regel: nicht mehr als 200 Zeilen. Wenn es überfüllt ist — bereinigt der Agent selbst: löscht Veraltetes, fasst Duplikate zusammen, behält nur Lebendiges.

  • «Ich heiße Thomas, ich leite einen Kurs über KI»
  • «Bot «Agenten-Konstruktor» — mein Hauptprodukt»
  • «Ich mag keine langen Antworten, komm auf den Punkt»
  • «Server auf Hetzner, Domain soundso, Backup auf Google Drive»

Ebene 2 — Tagesjournale memory/YYYY-MM-DD.md

Für jeden Tag — eine eigene Datei. Der Agent schreibt selbst hinein: was Sie heute besprochen haben, welche Aufgaben Sie erledigt haben, worüber Sie sich geeinigt haben. Ein Tag = eine Datei.

Warum so? Heute ein Landingpage, morgen Bot-Korrekturen, übermorgen ein Marketing-Gespräch. Wenn man alles in eine MEMORY.md kippt — ertrinkt sie in einer Woche. Wenn aber jeder Tag sein eigenes Blatt hat — sagen Sie entspannt «erinnerst du dich, was wir gestern zur Landingpage besprochen haben?» und der Agent öffnet die gestrige Datei und macht dort weiter.

Ebene 3 — knowledge/ (Nachschlagewerk-Bibliothek)

Hierher wandern thematische Kenntnisse, die zu umfangreich für MEMORY.md sind, aber ständig gebraucht werden: Projektarchitektur, Server-Configs, gefundene Lösungen, Rezepte. Eine Datei = ein Thema.

Einfaches Beispiel: Sie haben dreimal gefragt «wie ist mein Backup eingestellt?» — der Agent löst es einmal, schreibt die Datei knowledge/backup-config.md, und diese Frage stellen Sie nie wieder.

Was unterscheidet das von ChatGPT

Bei ChatGPT ist das Gedächtnis deren. Es liegt auf den Servern von OpenAI, wird durch deren Regeln reguliert. Beim Agenten — ein Ordner auf Ihrem Server. Heruntergeladen, archiviert, übertragen — fertig. Gesprächsverlauf, Persönlichkeit, Fakten, Nachschlagewerke — das gehört Ihnen.

Noch ein wichtiges Detail: Der Agent entscheidet selbst, was wohin kommt. ChatGPT speichert den gesamten Strom der Reihe nach, der Agent strukturiert — Wichtiges in MEMORY.md, Chronik ins Tagebuch, Themen in knowledge/. Nach einem Monat sehen Sie eine durchdachte Wissenskarte — keine chaotische Chat-Ablage.

Zwei Dateien — zwei Bedeutungen

USER.md — wer Sie sind: Name, Bereich, Gewohnheiten, Kommunikationston.

SOUL.md — Persönlichkeit des Agenten

Das ist die wichtigste Datei seiner «Seele». Sie liegt in ~/workspace/SOUL.md. Dort steht, wie der Agent sein soll:

  • Name, Stil, Ton, Sprache — zum Beispiel «Jarvis, warmer älterer Kamerad, per Sie, auf Deutsch».
  • Konstitution — fünf Prinzipien in Prioritätsreihenfolge. Das Wichtigste: «keine irreversiblen Aktionen ohne Bestätigung» (P1). Und «Ehrlichkeit» — wenn er es nicht weiß, sagt er «ich weiß es nicht», statt sich etwas auszudenken.
  • Drift-Detektor — eine Liste von Antimustern, die der Agent bei sich selbst bemerkt. «Ich habe drei Antworten hintereinander als Liste gegeben» — stopp, auf lebendige Sprache umschalten.
  • Antwortformat — kurze Absätze, ohne Hype-Emojis, ohne Floskeln «Natürlich!», «Tolle Frage!».
  • Verbotene Muster — konkrete Phrasen und Gewohnheiten, von denen der Agent sich fernhält.
🤔 Begriff: «Konstitution»

Fünf Regeln des Agenten, die er sich selbst über alles andere stellt. Wenn Sie ihn um etwas Gefährliches bitten — hält er inne nicht weil er «es nicht kann», sondern weil er es sich selbst verboten hat.

Diese Datei wird bei der ersten Einrichtung gefüllt, aber danach können Sie alles ergänzen was Sie möchten. Sie wollen, dass der Agent Sie «Chef» nennt — schreiben Sie es hinein. Sie wollen, dass er das Wort «kurz gesagt» nicht benutzt — schreiben Sie es in die verbotenen Muster.

USER.md — Ihr Profil

Das ist die Datei über Sie. Sie liegt in ~/workspace/USER.md. Die Aufgabe ist einfach — dem Agenten erzählen, mit wem er spricht:

  • Name, Bereich, Rolle — «Thomas, Experte für KI im Geschäftsbereich, leite Kurs».
  • Arbeitskontext — womit Sie sich beschäftigen, welche Aufgaben Sie lösen.
  • Technisches Niveau — «habe an der Uni Python geschrieben, Landingpages gebaut, stehe Code gelassen gegenüber».
  • Kommunikation — Text oder Sprache, Anredeform, wie viel Sie in einer Antwort lesen möchten.

Tagesjournale — die Chronik des Arbeitstages

Die Seite des Tagesplaners für heute. Bis abends gefüllt, morgens ein neues leeres Blatt.

Jeden Tag erscheint beim Agenten ein neues Blatt im Ordner ~/workspace/memory/. Die Datei heißt nach dem Datum — 2026-05-10.md. Der Agent trägt darin selbst, im Laufe des Tages, das Wichtigste ein: welche Aufgaben erledigt wurden, worüber man sich geeinigt hat, welche Probleme aufgetaucht sind, womit man aufgehört hat. Das ist sein Tagesjournal. Genau deshalb können Sie entspannt nach einer Woche sagen «erinnerst du dich, was wir am Mittwoch zur Landingpage besprochen haben?» — der Agent öffnet das passende Blatt und macht dort weiter.

Die wichtigste Botschaft

Das Journal ist kein Ablageort, sondern eine Ereignischronik

Ins Journal kommt, was heute passiert ist: Aufgaben, Entscheidungen, Ergebnisse. Keine allgemeinen Regeln (das ist MEMORY.md), keine tiefen Nachschlagewerke (das ist knowledge/). Einfach eine Chronik. Ein Tag — eine Datei. Alte Tage werden nicht gelöscht — sie werden zum langen Gedächtnis «wie wir zusammengearbeitet haben».

Was automatisch hineinkommt

Der Agent schreibt ins Journal ohne Erinnerungen. Standardinhalt:

  • Aufgaben und ihr Status — was begonnen, was beendet, was aufgeschoben wurde.
  • Getroffene Entscheidungen — «Thomas hat Blau für die Landingpage gewählt», «wir haben uns geeinigt, nur freitags zu deployen».
  • Gefundene Probleme und Lösungen — «Senden über Deepgram hat nicht funktioniert → Schlüssel in /settings geprüft → OK».
  • Tagesergebnis — kurze Notiz «was erledigt, was geblieben ist».
  • Ihre Ideen und Beobachtungen — was Sie im Format «müsste man probieren», «hier ein Gedanke», «kommen wir darauf zurück» gesagt haben.

Wie sich das Journal von MEMORY.md unterscheidet

Angenommen, Sie sagen: «Heute haben wir eine neue Landingpage für den Kurs gestartet. Adresse — course.example.de. Und generell machen wir jetzt alle Landingpages auf Vercel, nicht mehr auf Tilda wie früher.»

  • Im Tagesjournal: «2026-05-10 — neue Landingpage für den Kurs unter course.example.de gestartet». Das ist ein Ereignis.
  • In MEMORY.md: «Alle Landingpages werden jetzt auf Vercel gemacht (früher Tilda)». Das ist eine Regel für die gesamte weitere Arbeit.

Ein Gespräch — zwei Einträge in verschiedenen Schichten. In einem halben Jahr finden Sie «wann haben wir diese Landingpage gestartet?» — das steht im Journal vom 10. Mai. Und «wie machen wir Landingpages?» — das steht in MEMORY.md, immer griffbereit.

Wie man das benutzt

  • «Was haben wir gestern gemacht?» — der Agent öffnet das gestrige Blatt und erzählt.
  • «Was haben wir diese Woche gemacht?» — stellt eine Chronologie aus 5–7 Dateien zusammen.
  • «Erinnerst du dich, was wir am Montag zu X besprochen haben?» — findet die Erwähnung und gibt den Kontext.
  • «Wann haben wir diese Landingpage gestartet?» — geht durch die Journale und findet das Datum.
  • «Zeig die Ergebnisse der letzten drei Tage» — gibt eine kurze Zusammenfassung.

Sie müssen kein genaues Datum nennen. Sprechen Sie menschlich — «gestern», «letzte Woche», «Anfang Mai» — der Agent findet es selbst.

Was nicht ins Journal kommt

  • Technische Details auf 5 Bildschirmen — das ist knowledge/<thema>.md.
  • Regeln, die die gesamte Arbeit betreffen — das ist MEMORY.md.
  • Inhalt der .env, Schlüssel, Tokens — nirgendwohin, nur über /settings.

Wenn Sie möchten, dass eine Notiz sicher ins Journal kommt — sagen Sie: «Schreib ins heutige Journal, dass …». Das funktioniert explizit.

Was mit alten Tagen passieren soll

Sie verschwinden nirgendwohin — sie liegen alle in ~/workspace/memory/, angefangen vom ersten Tag. Nach einem Jahr gibt es 365 Dateien. Ein voller Ordner mit Journalen für ein Jahr belegt selten mehr als 5–10 Megabyte.

Manchmal schaut der Agent selbst in alte Journale. «Wann haben wir dieses Projekt zum ersten Mal besprochen?» — er geht ins Archiv und findet es. Das ist sein episodisches Langzeitgedächtnis: es verblasst nicht nach einem Monat, sondern liegt in voller Genauigkeit vor.

Mein Rat an Sie

Fragen Sie den Agenten einfach einmal pro Woche, am Freitag: «Fasse die Wochenergebnisse zusammen — was haben wir geschafft, was ist geblieben». Zwei Orte — zwei Zwecke

Der Agent lebt in zwei verschiedenen Ordnern auf dem Server. Beide sind wichtig, erfüllen aber unterschiedliche Aufgaben.

~/workspace/ — das Zuhause des Agenten. Hier liegen sein Gedächtnis (MEMORY.md), seine Persönlichkeit (SOUL.md), Ziele (GOALS.md) und alle Wissensdateien. Das ist keine Entwicklungszone, sondern sein persönlicher Bereich.

🐙 Was ist GitHub und warum brauchen wir es

6 Min · Abschnitt: Projekte & Deployment

GitHub — nicht nur Backup

GitHub ist ein Cloud-Dienst für die Speicherung von Code. Aber für uns erfüllt es zwei entscheidende Funktionen gleichzeitig: Backup und automatisches Deployment.

Drei Begriffe, die man kennen muss

Repository (Repo) — ein Projektordner auf GitHub. Enthält alle Dateien des Projekts sowie die vollständige Änderungshistorie. Beispiel: github.com/tervica11-svg/dirigent
Commit — eine gespeicherte Version des Projekts. Jeder Commit hat eine Nachricht ("Add VS Code section") und einen Zeitstempel. Man kann jederzeit zu einer beliebigen Version zurückgehen.
Push — lokale Commits auf GitHub hochladen. Erst nach dem Push sind die Änderungen in der Cloud sichtbar und werden von Vercel verarbeitet.

Typischer Arbeitsablauf

1. Datei geändert (Agent arbeitet) 2. git add dateiname.html 3. git commit -m "Beschreibung der Änderung" 4. git push origin main 5. GitHub erhält den Code 6. Vercel startet automatisch das Deployment 7. In 30–60 Sekunden ist die Website aktualisiert

Warum nicht einfach direkt speichern?

Weil der Server keine eigene öffentliche IP hat, die Nutzern zugänglich ist. GitHub ist der Mittelsmann zwischen dem Agenten-Server und dem Hosting (Vercel). Ohne GitHub würde Vercel nicht wissen, dass sich etwas geändert hat.

Außerdem: Wenn der Server abstürzt oder gelöscht wird, bleibt der gesamte Code auf GitHub erhalten. Das ist das eigentliche Backup.

🚀 Was ist Vercel und wie funktioniert Auto-Deployment

5 Min · Abschnitt: Projekte & Deployment

Vercel = Hosting + CDN + Auto-Deployment

Vercel ist ein Hosting-Dienst, der speziell für Entwickler optimiert ist. Er hostet nicht nur Websites, sondern aktualisiert sie automatisch, sobald sich der Code auf GitHub ändert.

Der vollständige Weg von Code zu Live-Website

Agent ändert Datei auf dem Server ↓ git push → Code geht zu GitHub ↓ GitHub benachrichtigt Vercel (Webhook) ↓ Vercel baut die neue Version (Build) ↓ In 30–60 Sekunden ist die Website live ↓ dirigent.vercel.app zeigt die aktuelle Version

Was Vercel noch leistet

CDN (Content Delivery Network) — Vercel verteilt die Website auf Server in verschiedenen Ländern. Nutzer in Deutschland erhalten die Seite von einem deutschen Server, Nutzer in Japan von einem japanischen. Ergebnis: schnelle Ladezeiten weltweit.
HTTPS automatisch — Vercel aktiviert SSL-Zertifikat automatisch. Die Website ist sofort über https:// erreichbar, ohne manuelle Konfiguration.
Preview-Deployments — Jeder Push auf einem anderen Branch erstellt eine separate Vorschau-URL. So kann man testen, bevor man auf main merged.

Verbindung zu GitHub einrichten

Einmalige Einrichtung: Vercel-Konto mit GitHub verbinden, Repository auswählen, Branch festlegen (main). Danach läuft alles automatisch. Jeder Push = automatisches Deployment.

💾 Was und wie man sichert

4 Min · Abschnitt: Projekte & Deployment

Drei Dinge, die regelmäßig gesichert werden müssen

Nicht alles auf dem Server ist gleich wichtig. Es gibt drei Kategorien, die bei einem Serverausfall oder versehentlichen Löschen nicht verloren gehen dürfen.

1. ~/workspace/ — das Gedächtnis des Agenten. MEMORY.md, SOUL.md, GOALS.md, alle knowledge/-Dateien. Diesen Ordner regelmäßig per git auf ein separates Repository sichern oder als Archiv herunterladen.
2. ~/.agent/.env — alle API-Schlüssel und Tokens. Dieser Wert existiert nur auf dem Server und ist nirgendwo sonst gespeichert. Verlust = alle Integrationen (Telegram, OpenAI, etc.) müssen neu eingerichtet werden. Einmalig lokal sichern.
3. GitHub-Repositories — der Code aller Projekte. Wenn man regelmäßig pusht, ist das automatisch gesichert. GitHub selbst ist das Backup.

Was NICHT separat gesichert werden muss

Alles, was bereits auf GitHub liegt, ist bereits gesichert. Node-Module (node_modules/), temporäre Dateien, Cache — das alles kann bei Bedarf neu generiert werden und braucht kein eigenes Backup.

Empfohlener Rhythmus

Täglich: git push (Code zu GitHub) Wöchentlich: workspace/ als ZIP herunterladen Einmalig: .env lokal speichern (sicher aufbewahren!)
Wichtig: .env niemals auf GitHub hochladen — es enthält geheime Schlüssel. GitHub-Repositories sind öffentlich oder halbpublic, .env muss lokal bleiben.

Was ist MCP und wozu braucht der Agent es

MCP ist eine universelle Steckdose. Der Agent steckt den Stecker ein — und bekommt Zugang zu einem neuen Dienst, ohne Programmierung.

Ihr Agent kann mit Dateien arbeiten, im Internet suchen, Code schreiben. Aber manchmal braucht man mehr: ein Mockup im Design-Editor öffnen, Daten von einer Website abrufen, eine Automatisierung starten. Dafür gibt es MCP — ein Protokoll, das dem Agenten ermöglicht, sich mit externen Tools zu verbinden.

Die universelle Steckdose

MCP (Model Context Protocol) ist ein Standardanschluss zwischen dem Agenten und externen Diensten. Ein Protokoll, ein Verbindungspunkt, Dutzende Möglichkeiten. Sie müssen die API jedes Dienstes nicht verstehen — es reicht, den «Stecker» in die Konfiguration einzustecken.

Wie es funktioniert

Ohne MCP — der Agent kann im Internet suchen und mit Dateien auf dem Server arbeiten. Das reicht für viele Aufgaben, aber nicht für alle.

Mit MCP — der Agent bekommt direkten Zugang zu externen Diensten: Kalender, E-Mail, Tabellen, Design-Editor. Er sieht die Möglichkeiten des Dienstes und ruft die benötigten Aktionen selbst auf — ohne Ihre Hilfe.

🖥 Agent (Claude Code CLI) │ ├── 📁 Dateien auf dem Server (eingebaut) ├── 🌐 Internet und curl (eingebaut) │ └── 🔌 MCP-Server (~/.claude.json) ├── pencil Design-Editor ├── supadata Website-Daten └── ... beliebiger MCP-Server

Was bereits vorinstalliert ist

Pencil — ein Tool für die Arbeit mit Design-Mockups (Dateien .pen). Der Agent kann Mockups öffnen, deren Inhalt lesen, Änderungen vornehmen, Screenshots machen und Elemente exportieren. Alles direkt aus Telegram, ohne ein separates Programm zu öffnen. Pencil läuft lokal auf Ihrem Server und sendet keine Daten nach außen.

Zwei Verbindungstypen

Lokal (stdio) — das Programm läuft direkt auf Ihrem Server (Beispiel: Pencil). Daten verlassen den Server nicht — sicherer.

Cloud (http) — der Agent wendet sich an einen Dienst im Internet (Beispiel: Supadata, Google Calendar). Daten werden über das Netzwerk übertragen — geeignet für externe Dienste.

Wo die Konfiguration gespeichert ist

Alle verbundenen MCP-Server sind in einer einzigen Datei gespeichert:

~/.claude.json → Abschnitt mcpServers

Claude Code liest diese Datei bei jedem Start. Neuen Server hinzugefügt — bei der nächsten Nachricht sieht der Agent ihn bereits.

Unterschied zwischen MCP und API-Schlüsseln

In /settings fügen Sie Schlüssel zu Diensten hinzu. Der Agent verwendet sie manuell — er bildet Anfragen an jeden Dienst selbst.

MCP funktioniert einfacher: Der Agent verbindet sich mit dem Dienst und sieht eine Liste fertiger Aktionen. Dann ruft er die benötigte auf — der Dienst kümmert sich selbst um die Details.

Analogie: Ein API-Schlüssel ist wie eine Telefonnummer. Sie rufen selbst an und sagen, was Sie brauchen. MCP ist wie ein Sekretär: Sie nennen die Aufgabe, und er weiß selbst, wen er anrufen und was er sagen soll.
Probieren Sie es jetzt aus: Pencil ist bereits verbunden. Schicken Sie dem Agenten eine .pen-Datei oder bitten Sie: «Zeig mein Mockup». Wenn es funktioniert — MCP ist bei Ihnen richtig konfiguriert.

Wie man einen MCP-Server verbindet — Schritt-für-Schritt

Eine JSON-Datei, zwei Zeilen Konfiguration — und der Agent beherrscht einen neuen Trick.

Die gesamte MCP-Konfiguration lebt in einer einzigen Datei — ~/.claude.json. Neuen Server hinzufügen = einen Block in diese Datei eintragen. Entfernen = Block löschen. Kein Neustart — der Agent übernimmt die Änderungen bei der nächsten Nachricht.

Eine Datei — alle Verbindungen: ~/.claude.json → Abschnitt mcpServers. Block hinzugefügt — Server verbunden. Block gelöscht — Server getrennt.

Methode 1: Den Agenten bitten

Der einfachste Weg — sagen Sie dem Agenten direkt im Chat:

«Verbinde MCP-Server supadata, URL: https://mcp.supadata.dev/v1»

Der Agent liest ~/.claude.json selbst, fügt einen neuen Eintrag in den Abschnitt mcpServers ein und schreibt die Datei zurück. Sie müssen keine Dateien von Hand öffnen.

Methode 2: Über VS Code

Wenn Sie VS Code Tunnel verbunden haben (/connect), können Sie die Datei manuell bearbeiten:

1. VS Code öffnen 2. Datei ~/.claude.json öffnen 3. Abschnitt "mcpServers" finden (oder erstellen, falls nicht vorhanden) 4. Block des neuen Servers eintragen und speichern

Konfigurationsformat

Die Datei ~/.claude.json sieht so aus:

{ "mcpServers": { "pencil": { "type": "stdio", "command": "/home/agent/.pencil/mcp/visual_studio_code/out/mcpserver-linux-x64", "args": ["--app", "visual_studio_code"], "env": {} }, "supadata": { "type": "http", "url": "https://mcp.supadata.dev/v1" } } }

Typ stdio — Programm auf dem Server

Wird verwendet, wenn der MCP-Server ein Programm ist, das auf Ihrem VPS läuft.

{ "type": "stdio", "command": "/pfad/zum/programm", // oder "npx", "node" "args": ["argument1", "argument2"], "env": {} // Umgebungsvariablen (API-Schlüssel) }

Bei jedem Start startet Claude Code dieses Programm und kommuniziert über stdin/stdout. Wenn die Sitzung endet — wird der Prozess gestoppt.

Typ http — Remote-Server

Wird verwendet, wenn der MCP-Server in der Cloud unter einer URL läuft.

{ "type": "http", "url": "https://server-adresse/pfad", "headers": { "Authorization": "Bearer ihr_token" } }

MCP-Server entfernen

Über den Agenten: Sagen Sie «Trenne MCP-Server supadata» — der Agent entfernt den Eintrag aus ~/.claude.json.

Manuell: Öffnen Sie ~/.claude.json über VS Code, löschen Sie den Block des gewünschten Servers aus mcpServers, speichern Sie.

Prüfen, was verbunden ist

Bitten Sie den Agenten: «Welche MCP-Server habe ich verbunden?» — der Agent liest ~/.claude.json und zeigt die Liste.

Häufige Fehler

MCP-Server erscheint nicht nach dem Hinzufügen. Der Agent liest die Konfiguration beim Start einer neuen Sitzung. Server während eines aktiven Gesprächs hinzugefügt — machen Sie /reset, und bei der nächsten Nachricht verbindet sich der Agent mit dem neuen Server.
Fehler «command not found» für stdio-Typ. Das Programm ist nicht auf dem Server installiert. Wenn der MCP-Server npx erfordert — prüfen Sie, ob Node.js installiert ist. Wenn es eine Binärdatei ist — prüfen Sie den Pfad in command und die Ausführungsrechte (chmod +x).
Autorisierungsfehler für http-Typ. Prüfen Sie, ob URL und Header korrekt angegeben sind. Wenn der Server einen API-Schlüssel erfordert — fügen Sie ihn in headers oder env ein.

5 Beispiele — was man mit MCP machen kann

MCP verwandelt den Agenten vom Gesprächspartner zur Arbeitsmaschine. Kalender verbunden — der Agent plant Meetings. E-Mail verbunden — er schreibt und antwortet.

MCP ermöglicht dem Agenten, direkt mit externen Diensten zu arbeiten — nicht durch Hin- und Herkopieren von Daten, sondern durch direkte Verbindung. Hier sind fünf Beispiele für Alltags- und Geschäftsaufgaben.

Jeder MCP-Server gibt dem Agenten eine Reihe neuer Aktionen. Nach der Verbindung beschreiben Sie die Aufgabe einfach in normalen Worten — der Agent ruft die benötigte Aktion aus dem verbundenen Dienst selbst auf.

1. Google Calendar — Tagesplanung

Nach der Verbindung des Kalenders sieht der Agent Ihren Terminplan, erstellt Ereignisse, sucht freie Zeitfenster und erinnert an Meetings.

«Welche Termine habe ich heute?» «Plane ein Meeting mit Anna für Donnerstag 15:00, Thema — Content-Plan-Besprechung» «Finde ein freies Zwei-Stunden-Fenster nächste Woche» «Erinnere mich jeden Morgen um 8:00, was für den Tag geplant ist»

2. Gmail — E-Mail ohne E-Mail zu öffnen

Der Agent liest den Posteingang, schreibt Entwürfe, antwortet auf E-Mails und sortiert nach Wichtigkeit. Sie öffnen keinen E-Mail-Client — alles über Telegram.

«Zeig mir ungelesene E-Mails von heute» «Schreib eine Antwort an Thomas: Danke, alles erhalten, wir treffen uns am Mittwoch» «Finde alle E-Mails von der Sparkasse im letzten Monat» «Sortiere den Posteingang: was dringend, was kann warten, was Spam»

3. Google Sheets — Tabellen und Berichte

Der Agent arbeitet direkt mit Tabellen: liest Daten, fügt Zeilen hinzu, berechnet Summen, erstellt Übersichten. Ideal für Buchhaltung, CRM, Finanzen.

«Öffne Tabelle "Verkäufe April" und zeig die Summe der Spalte "Betrag"» «Füge zur Kundentabelle hinzu: Müller Hans, +49-123-456789, Anfrage für Beratung» «Erstelle eine Wochenzusammenfassung der Verkäufe aus Tabelle "CRM"» «Exportiere die Kundenliste, die seit mehr als 30 Tagen nicht gekauft haben»

4. Pencil — Design-Mockups aus Telegram

Dieser MCP-Server ist bereits vorinstalliert. Der Agent kann Mockup-Dateien (.pen) öffnen, Texte und Farben ändern, Bilder exportieren — direkt aus Telegram.

«Öffne das Visitenkarten-Mockup und ändere die Telefonnummer auf +49-000-000-0000» «Erstelle einen Screenshot der Hauptseite aus dem Mockup landing.pen» «Exportiere das Logo aus dem Mockup als PNG»

5. Website-Daten — Analyse und Monitoring

Supadata — ein MCP-Server für das Abrufen von Informationen von Webseiten. Verbindet sich ohne API-Schlüssel, kostenlos. Nützlich für Wettbewerbsbeobachtung, Content-Sammlung, Marktanalyse.

«Hol den Text des Artikels von dieser URL und mach eine kurze Zusammenfassung» «Erstelle eine Transkription dieses YouTube-Videos» «Sammle Produktbeschreibungen von dieser Seite und formatiere sie als Tabelle»
Übersicht:
Planung → Google Calendar | Terminplan, Meetings, Erinnerungen
E-Mail → Gmail | Lesen, Antworten, Sortieren
Tabellen & CRM → Google Sheets | Kundenverwaltung, Verkäufe, Berichte
Design → Pencil | Mockups, Bilder, Visitenkarten (vorinstalliert)
Analyse → Supadata | Website-Daten, Video-Transkriptionen (kostenlos)
Tipp: Beginnen Sie mit dem, was Sie täglich verwenden. Wenn Sie den ganzen Tag in der E-Mail sind — verbinden Sie Gmail. Wenn Sie Kunden in einer Tabelle verwalten — Google Sheets. Wenn Sie viele Termine haben — Google Calendar. Verbinden Sie nicht alles auf einmal: einen Dienst, ausprobiert, gewöhnt — dann den nächsten.
